## 2. 现状盘点（决定方案空间的事实）

1. **`apps/web` 不是静态站**：含 18 个 API 路由（`/api/search`、`/api/detail`、`/api/proxy/[url]`、`/api/live/stream/[url]`、`/api/douban`、`/api/auth`、`/api/quality`、`/api/publish`、`/api/source-list` 等），需要 Node.js 运行时。
   → **纯静态托管（GitHub Pages 等）直接排除**，除非做"客户端直连化"改造（§9 远期选项）。
2. **发布产物已齐备**：`web-standalone`（node server.js 直跑包）与 `web-docker`（GHCR 多架构镜像 `ghcr.io/xiaowulai-s/littlesu-tv:latest`）两条流水线随 `v*` 标签发布。
   → **任何能跑容器的免费平台都能零改动接入**。
3. **公网安全项已内置**：`.env.example` 提供 `PASSWORD`（访问密码）、`PROXY_SECRET`（代理签名密钥，缺省从 PASSWORD 派生）、`COOKIE_SECURE`、`REQUEST_TIMEOUT`、`DEFAULT_SUBSCRIPTIONS`。
4. **构建模式**：`next.config.ts` 按 `DOCKER_BUILD=1` 切换 standalone 输出；Vercel 走默认模式即可，无冲突。
5. **上游依赖**：采集源 25 个（内置清单）、豆瓣/榜单经服务端请求（榜单默认走 `60s.viki.moe` 公共实例，每小时仅 6 次请求）。

## 3. 流量模型（免费额度能否扛住的关键）

| 路径 | 方向 | 量级 | 占服务器流量？ |
|---|---|---|---|
| 页面资源（首访） | 服务器 → 浏览器 | ~2 MB/新访客 | ✅ 是（100GB/月 ≈ 5 万新访客） |
| 搜索/详情/榜单 JSON | 服务器 ↔ 上游 | KB 级 | ✅ 是（可忽略） |
| **播放 m3u8/ts** | **浏览器 → 资源站直连** | 大 | ❌ **否**（hls.js 直连，架构决定免费额度可行） |
| `/api/proxy` 兜底 | 服务器 → CORS 失败源 | 中 | ✅ 是（仅兜底启用） |
| `/api/live/stream` | 服务器 → 直播源 | 大 | ✅ 是（**开启即吃流量，需评估**） |

**结论**：点播场景下服务器只承担"页面 + JSON + 兜底"，个人使用 100GB/月绰绰有余。两个流量风险点：直播流代理、无密码公开模式下的 proxy 滥用（见 §7）。

## 5. 推荐架构（主方案 A + 两层可选增强）

### 5.1 主方案 A：Vercel Hobby（零改动，先跑起来）

```
GitHub 仓库 → Vercel 自动构建（Root Directory = apps/web）
           → 18 个 API 路由跑在 Vercel Functions（Node runtime）
           → 页面走 Vercel Edge CDN
```

- **部署触发**：Vercel Git 集成，`main` 分支 push 自动部署（建议限定 paths `apps/web/**` 避免客户端提交触发无效构建）；与现有 `v*` 标签流水线两轨并行互不干扰。
- **环境变量（Vercel Dashboard 配置）**：

| 变量 | 值 | 必要性 |
|---|---|---|
| `PASSWORD` | 强密码 | **必设**（公开模式 = proxy 裸奔） |
| `PROXY_SECRET` | 随机长串 | 建议显式设置 |
| `DEFAULT_SUBSCRIPTIONS` | `["https://raw.githubusercontent.com/xiaowulai-s/LittleSU/main/sources/littlesu-sources.json"]` | 建议（复用仓库内置源清单） |
| `REQUEST_TIMEOUT` / `MAX_RETRIES` | 8000 / 1 | 默认即可 |

- **额度评估**：Functions 最长 300s（Fluid），本项目 API 上游超时仅 8s，远低于上限；4 CPU-h ≈ 每天数千次动态请求，个人使用富余。
- **验收冒烟**：搜索出结果 → 点播可播（确认播放流量走直连）→ 密码门禁生效 → 直播页可用。

### 5.2 增强层：自定义域名 + Cloudflare（决策：跳过，留档备查）

> **2026-10-31 决策：自用 + 国内走腾讯云入口，本层不需要，跳过实施。** 以下留档备未来参考。

- 现状：`vercel.app` / `pages.dev` / `workers.dev` 在大陆长期被 DNS 污染（移动宽带最明显），**默认域名仅适合海外/自用**。
- 手段：自有域名 DNS 托管到 Cloudflare（免费计划）→ CNAME 指向 Vercel（灰云仅 DNS 完成验证；可换优选 CNAME 节点进一步改善）。
- 域名来源三选一：
  1. 低价域名 `.top` / `.xyz` 首年 ¥5-10（推荐，省心）；
  2. 免费域名 `eu.org`（0 元，审核数周）；
  3. 不买域名，接受国内访问不稳（0 元）。
- **预期**：显著改善但不保证；上线后用三网（移动/联通/电信）实测。

### 5.3 备份层：Render 免费实例（可选）

- 直接拉现有镜像 `ghcr.io/xiaowulai-s/littlesu-tv:latest`，零构建配置。
- 15 分钟休眠可接受（备份入口不常访问）；同样配置 `PASSWORD`。
- 价值：Vercel 故障/额度耗尽时的第二入口，并验证 Docker 路线。

### 5.4 国内直连层：腾讯云服务器（✅ 已确认启用）

服务器：106.54.229.143（已承载 Dynamic-Management，边际成本 0）。**用途**：国内无梯设备（手机/电视）的直连入口。

**部署方式二选一（实施时定，推荐方式①）**：

| 方式 | 做法 | 优点 | 注意 |
|---|---|---|---|
| ① standalone + pm2（推荐） | 下载 Release 的 `web-standalone` 包 → `node server.js`（需 Node 18+）→ pm2/systemd 守护 | 绕开 GHCR 国内拉取慢的问题；资源占用小 | 无 Docker 层，升级 = 换包重启 |
| ② docker compose | `apps/web/docker-compose.yml`，镜像 `ghcr.io/xiaowulai-s/littlesu-tv:latest` | 与现有流水线一致，升级 = pull | 腾讯云拉 GHCR 需配镜像加速，可能不稳 |

**关键配置**：

- 端口：非常规端口（建议 **8090**，避开在用的 9000），安全组仅放行该端口
- 环境变量：`PASSWORD`（同 Vercel 或单独一份）、`PROXY_SECRET`；HTTP 部署 `COOKIE_SECURE` 无需配置（项目已按协议自动推导）
- 无域名：`http://106.54.229.143:8090` 直接用；未备案域名不能走 80/443，本项目不需要域名
- 国内 IP 请求采集源/豆瓣：速度与成功率优于海外机房（豆瓣反爬风险反而降低）
- **合规**：内容聚合站部署于国内服务器，风险自担；强密码 + 仅私人使用 + 不对外分享链接

## 6. 安全与滥用防护（公网上线必做）

1. **`PASSWORD` 必设**：当前不设即公开模式。无签名时 `/api/proxy` 是开放转发器，可被盗用刷爆免费额度、当跳板——这是免费部署的头号翻车点。
2. **`PROXY_SECRET` 显式设置**，避免从 PASSWORD 派生的弱熵。
3. Vercel 免费自带 DDoS 缓解；可用免费额度的 **3 条 WAF 自定义规则**封禁异常 IP/路径。
4. 额度监控：Vercel 在 80% / 100% 用量自动发邮件；`Fast Data Transfer` 超限后项目暂停（不会产生账单，免费层无超额计费）。
5. **直播流代理（定稿默认）**：自用 + 双端均设 `PASSWORD` 的前提下保留现有行为，不加代码改动；P2 观察两端流量用量，若 Vercel 端传输异常增长再关闭/加鉴权（届时属代码改动，另行批准）。

## 7. 合规与风险边界

- **Vercel Hobby 条款**：仅限个人非商业项目——本项目个人维护可，勿挂广告/收费/商用。
- **内容**：本项目不存储视频，仅聚合第三方公开接口；README 免责声明保留即可。
- **国内服务器/IP 部署**：未备案域名无法 80/443；内容审查风险自担；建议仅私人强密码访问。
- **豆瓣反爬**：海外机房 IP 请求豆瓣可能被限流；榜单默认走 60s 公共实例已缓解，必要时可关闭豆瓣模块降级运行。
